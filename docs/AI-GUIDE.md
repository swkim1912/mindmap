# 마인드맵 앱 — AI 작성 가이드

> **이 문서를 통째로 Claude 채팅이나 다른 AI에게 붙여넣고 요청하세요.**
> AI가 `.mm.md` 형식의 마크다운을 만들어 주면, 사이트의 **⇅ → 가져오기**(파일) 또는 **텍스트 붙여넣기**로 새 맵을 만들 수 있습니다.
>
> 이 문서의 핵심 약속 두 가지
> 1. **내용을 줄이지 않는다.** 마인드맵은 깔끔한 요약본이 아니라 원자료의 **전체 내용을 담는 노트**입니다. (§3)
> 2. **6단계 논리구조**로 정리한다. 강의 제목부터 가장 깊은 세부 내용까지 6개 레벨로 계층을 잡습니다. (§4)

## 1. 사람을 위한 사용법 (1분)

### 강의자료·교재를 맵으로 정리하게 하기
1. 이 문서 전체를 AI 채팅에 붙여넣습니다. (사이트의 ⇅ 대화상자 → **AI 가이드 복사** 버튼으로 복사할 수 있습니다.)
2. 정리할 자료를 붙여넣거나 첨부(PDF·슬라이드·필기 사진 등)하고 요청합니다. 예:
   - "위 가이드대로 이 강의자료를 **6단계 구조로, 내용 누락 없이** 맵으로 만들어 줘." (§10의 요청 예시 복사)
3. AI가 **코드블록 하나**로 준 마크다운을 복사합니다.
4. 사이트에서 가져옵니다.
   - **붙여넣기:** ⇅ → "붙여넣은 내용으로 새 맵 만들기" (폰에서 가장 편함)
   - **파일:** `이름.mm.md` 로 저장해서 ⇅ → "파일로 가져오기"
5. 가져온 뒤 맵 위쪽에 **⚠ 해석 경고**가 있으면 마우스를 올려 어느 줄이 문제인지 확인하고, 그 내용을 AI에게 알려 고쳐 달라고 하세요.

### 분량이 많을 때
AI는 줄여서 맞추지 않고 **대주제(레벨 1) 단위로 나눠서** 출력합니다 (§3-8). 끊기면 "계속"이라고 입력하세요. 파트마다 별도 맵으로 가져와집니다 (`… (1/3)`, `… (2/3)`).

### 빠졌는지 확인하기
AI가 마지막에 **누락 점검 보고**(원자료 단위별 반영 여부, 의도적으로 제외한 것, 판독 불가한 것)를 씁니다. 그래도 불안하면 §10의 "누락 점검" 요청을 쓰세요.

### 이미 있는 맵을 AI에게 고치게 하기
1. 사이트에서 맵을 열고 **⇅ → Markdown(.mm.md)** 으로 내보냅니다. (또는 Vault 폴더의 `.mm.md` 파일)
2. 파일 내용을 AI에게 주고 "노드 ID(`^abcd`)는 바꾸지 말고 이렇게 고쳐 줘: …" 라고 요청합니다.
3. AI가 준 **전체 파일**을 가져옵니다. 같은 이름이 있으면 `이름 (2)` 로 새로 만들어지므로 비교한 뒤 옛 맵을 삭제하세요.
   - PC에서 Vault 폴더를 직접 쓰고 있다면 그 파일에 덮어쓰면 열린 화면에 바로 반영됩니다.

### 가져올 수 있는 것
| 형식 | 결과 |
|---|---|
| **이 문서의 형식 (`.mm.md`, `.md`)** | 태그·색·메모·카드 문법까지 그대로. 확장자가 `.md` 여도 내용을 보고 자동 판별 |
| 일반 마크다운 (제목 `#` + 목록 `-`) | 제목과 목록 구조만 가지로 (속성·메모 문법 없음) |
| OPML, XMind(.xmind) | 구조와 메모 |

> **페이지(긴 설명 문서)는 가져오기로 만들 수 없습니다.** 구조로 풀기 어려운 긴 인용·코드·수식은 노드의 **메모(포스트잇, `> 📌`)** 안에 쓰세요. 메모는 마크다운을 전부 지원합니다. (PC에서 Vault 폴더에 직접 파일을 둘 수 있다면 §9 참고)

## 2. AI에게: 출력 형식 규칙 (반드시 지킬 것)

당신은 **마인드맵 앱용 파일**을 만드는 도우미입니다. 사용자가 자료를 주면 아래 규칙으로 `.mm.md` 를 출력하세요. 내용을 어떻게 담을지는 §3·§4가 정합니다.

1. **파일 전체를 코드블록 하나**에 담아 출력합니다. 코드블록은 ` ````markdown ` (백틱 4개)로 열고 ` ```` ` 로 닫으세요. 메모 안에 백틱 3개짜리 코드블록이 들어갈 수 있기 때문입니다. (§5의 `md` 블록은 문법 조각을 보여 주는 설명용이고, 출력할 파일은 §7 처럼 완성된 `markdown` 블록 하나입니다.)
2. 인사·설명·보고는 **코드블록 밖**에 쓰세요. 코드블록 안에는 파일 내용만 둡니다. (누락 점검 보고도 코드블록 밖에 씁니다. §3-9)
3. 맨 위에 frontmatter(`---` 블록), 그다음 `# 중심 주제` 한 줄, 그 아래에 들여쓰기 목록(`- `)으로 가지를 씁니다.
4. frontmatter의 `title:` 값에 **콜론(`:`)이 있으면 반드시 큰따옴표로 감싸세요.** 예: `title: "10주차: 객관적 성격검사"` (감싸지 않으면 해석 경고가 납니다.)
5. **들여쓰기는 공백 2칸**입니다. 탭을 쓰지 마세요. 자식은 부모보다 정확히 한 단계(2칸)만 깊게 쓰고, 단계를 건너뛰지 마세요.
6. **노드 ID(`^abcd`)를 새로 만들지 마세요.** 새 노드는 ID 없이 쓰면 앱이 붙입니다. (예외: 같은 맵 안 연결 링크가 필요할 때만 §5.7)
7. **이미지는 쓰지 마세요.** (노드에는 이미지를 넣을 수 없고, 가져오기로 이미지 파일을 만들 수도 없습니다.) 그림·도식은 §4-3처럼 글로 풀어 쓰세요.
8. 목록(`- `) 밖의 일반 문단은 맵에 표시되지 않습니다. 내용은 반드시 노드(또는 메모) 안에 두세요.
9. 수정 요청이면: **기존 노드의 ID와 `{속성}` 은 그대로 유지**하고, 파일 전체를 다시 출력하세요.
10. 노드 하나는 **원자료의 정보 단위 하나**(한 개념, 한 문장, 한 수치 묶음)입니다. 글자 수 제한은 없습니다. 부연은 같은 노드 안에서 줄바꿈합니다(§5.4).
11. 강의자료·교재 정리에는 frontmatter에 **`layout: logic-right`** 를 권장합니다. (깊고 넓은 계층은 오른쪽으로 펼치는 레이아웃이 읽기 쉽습니다.) 개념 지도처럼 중심에서 퍼지는 구조는 `mindmap`.

## 3. AI에게: 내용 원칙 — **전체 보존 (최우선)**

이 앱의 맵은 **요약본이 아닙니다.** 원자료를 다시 펼쳐 보지 않고도 **시험 범위 전체를 복습**할 수 있어야 합니다. 이 장의 원칙은 §4의 6단계 정리 원칙과 충돌할 때 **항상 이 장이 이깁니다.**

1. **우선순위: 누락 없음 > 정확한 구조 > 간결함.** 간결함은 가장 마지막입니다.
2. **모든 정보 단위를 반영**합니다. 문장, 정의, 수치와 단위, 고유명사, 연도·인명, 예시·사례·반례, 예외, 조건과 단서("단", "다만", "~인 경우"), 부정 표현, 구분 기준, 번호·순서, 표의 **모든 셀**, 그림·도식이 전달하는 내용, 각주, 원자료의 암기 문구·두문자어.
3. **줄이는 것은 '표현'뿐입니다.** 문체를 개조식(~함, ~됨, 명사형, `->`)으로 정돈하는 것은 허용하지만, 이는 어미를 정리하는 것일 뿐 **정보를 덜어내는 근거가 아닙니다.** 원문의 용어·수치·고유명사는 그대로 쓰고, 문장 순서도 원자료를 따릅니다. 같은 내용이 반복될 때만 합칠 수 있으며, 합칠 때 어느 한쪽의 정보도 잃지 마세요.
4. **중요도를 스스로 판단해 빼지 마세요.** "덜 중요해 보여서", "너무 세부적이라서"는 제외 사유가 아닙니다. 중요도 판단은 사용자의 몫입니다. 판단이 서지 않으면 **넣으세요.**
5. **원자료에 없는 내용을 덧붙이지 마세요.** 이해를 돕는 보충이 꼭 필요하면 해당 노드의 메모(`> 📌`)에 `[AI 보충]` 표시를 붙여서 원문과 구분하세요.
6. **의도적으로 제외해도 되는 것**은 쪽번호, 반복되는 머리글·바닥글, 로고, 순수 장식 이미지, (내용이 본문에 다 있는) 목차 페이지뿐입니다. 이 밖의 것을 제외했다면 반드시 보고(§3-9)하세요.
7. **읽을 수 없거나 모호한 부분**(흐린 스캔, 잘린 도표 등)은 추측해서 채우지 말고 노드에 `[판독불가]` 또는 `[확인 필요: 이유]` 로 표시하고 보고하세요.
8. **분량이 많으면 줄이지 말고 나눠서 출력**하세요.
   - **레벨 1(대주제) 경계**에서 끊습니다. 각 파트는 그 자체로 완전한 `.mm.md` 이고, 중심 주제 끝에 `(1/3)`, `(2/3)` 처럼 번호를 붙입니다. (`title:` 도 같게)
   - 끊을 때는 "계속하려면 '계속'이라고 입력하세요"라고 알리고 기다립니다. 다음 파트는 **이어서** 시작합니다. 앞 내용을 다시 요약하거나 건너뛰지 마세요.
   - 마지막 파트 뒤에 전체 누락 점검 보고를 씁니다.
9. **누락 점검 보고** (코드블록 밖, 짧게):
   - (a) 원자료 단위(슬라이드 번호, 페이지, 절)별로 **반영했음**을 확인한 범위
   - (b) 의도적으로 제외한 항목과 이유
   - (c) `[판독불가]`·`[확인 필요]` 로 표시한 항목
   - (d) 만든 대주제(레벨 1) 목록
10. **누락 점검 요청을 받으면** 원자료와 맵을 처음부터 대조해, 빠진 항목을 "어느 노드 아래에 무엇을 추가할지"로 먼저 나열하세요. 사용자가 확인하면 반영한 **전체 파일**을 다시 출력합니다.

## 4. AI에게: 6단계 논리구조

모든 내용은 아래 6개 레벨 중 하나로 정리합니다. 레벨은 **논리적 깊이**입니다. 특정 과목·문서 형식에 의존하지 않습니다.

### 4-1. 레벨과 이 앱에서의 표기

| 레벨 | 논리적 의미 | 명칭 | 이 앱에서 쓰는 위치 | 들여쓰기 |
|---|---|---|---|---|
| 0 | 강의/주차 제목 | 강의 제목 | `# 제목` (중심 주제) | — |
| 1 | 대주제 (한 화면~한 절 단위의 큰 주제) | 대주제 | 첫 번째 단계 `- ` | 0칸 |
| 2 | 대주제 안의 묶음 | 세부주제 | 그 자식 | 2칸 |
| 3 | 핵심 항목 | 내용 | 그 자식 | 4칸 |
| 4 | 항목의 부연·구성요소 | 보조 내용 | 그 자식 | 6칸 |
| 5 | 가장 깊은 디테일 | 세부 내용 | 그 자식 | 8칸 |

- 레벨 구분용 기호(■ ● ○ ✓ 등)는 **쓰지 않습니다.** 깊이는 들여쓰기가 나타내고 앱이 모양을 정합니다.
- 맵 하나 = 강의(주차) 하나입니다. 중심 주제가 레벨 0입니다.

```
레벨0  # 10주차: 객관적 성격검사
레벨1  - 성격의 측정
레벨2    - 정의적 특성을 측정하는 방법
레벨3      - 투사적 방법
레벨4        - 모호한 자극 제시
레벨5          - 무의식적 느낌·정서·태도를 이끌어냄
```

### 4-2. 레벨 배정 원칙
- **제목성(0~1)과 항목성(3~5)을 먼저 가릅니다.** 슬라이드 제목, 장·절 헤더, 굵은 대문 문구는 레벨 0~1. 그 아래 불릿·문장은 레벨 3 이하.
- **부모-자식 관계로 깊이를 정합니다.** "A는 B, C, D로 구성된다"에서 A는 부모 레벨, B·C·D는 한 단계 깊은 자식 레벨. 들여쓰기는 의미적 **종속**을 보여주는 것이지 분량 균형을 맞추는 것이 아닙니다.
- **형제 항목은 같은 레벨로 통일합니다.** 같은 분류 기준에서 나온 항목(척도, 단계, 유형 등)은 모두 같은 레벨에 둡니다.
- **레벨을 건너뛰지 않습니다.** 레벨 1 바로 다음에 레벨 4가 오지 않게 합니다. 원자료에 중간 헤더가 없으면, 그 묶음의 내용을 **빠짐없이 아우르는 짧은 헤더**를 만들어 넣으세요. (헤더를 만들 때도 아래 내용은 하나도 줄이지 않습니다.)
- **깊이는 보통 레벨 5까지**입니다. 더 깊어지면 상위 항목을 분리하거나 형제 레벨로 평탄화하세요. 내용을 버려서 깊이를 맞추면 안 됩니다.
- **나열형 항목은 한 노드에 몰아넣지 않습니다.** 여러 구성요소·소척도는 부모 항목 한 줄 아래에 한 레벨 낮춰 **개별 노드**로 분리합니다. (예: "15개 소척도로 구성"은 레벨 3, 그 아래 15개를 각각 레벨 4)
- **부연 설명은 같은 노드 안에서 줄바꿈**합니다. 보충 설명 때문에 새 노드를 만들 필요가 없을 때는 §5.4의 여러 줄 노드를 쓰세요.

### 4-3. 원자료 형태별 처리

| 원자료 형태 | 처리 방법 |
|---|---|
| 불릿/들여쓰기 목록 | 원자료의 들여쓰기 깊이를 레벨 깊이에 대응. 최상위 불릿이 주제 헤더면 레벨 2, 핵심 항목이면 레벨 3 |
| 정의/개념 문장 | "용어: 설명" 형태는 용어를 항목으로 두고, 설명은 같은 노드 안 줄바꿈 또는 한 단계 아래 보조 레벨로 |
| 표(table) | 구조를 그대로 옮기지 않고 행을 항목으로, 열을 "이름: 값" 또는 줄바꿈 설명으로 풀어 **텍스트 계층**으로 재구성. **모든 셀의 값을 빠짐없이** 옮김 |
| 그림/도식/그래프 | 시각요소 대신 그것이 전달하는 관계·수치·분류를 글로 풀어 씀 (예: 그래프 → "T점수 65 이상이면 임상적 상승"). 축·범례·수치도 포함 |
| 순서 있는 절차/단계 | 단계 묶음을 레벨 3, 각 단계를 레벨 4로. 순서가 중요하면 `1) 2) 3)` 을 직접 적어 보존 |
| 예시/사례 박스 | 관련 항목 아래 한 단계 깊은 레벨에 `예: …` 로 배치 |

### 4-4. 표현 원칙 (§3이 우선)
- **개조식 문체**: "~함", "~됨", "~필요", "~주의", "~가능" 또는 명사형으로 끝맺습니다. 예: "T점수가 65 이상이면 임상적으로 의미가 있다고 해석한다." → `65T 이상 -> 임상적으로 의미있는 상승`
- **조사·서술어 생략은 뜻이 흐려지지 않는 선에서만.** 인과·조건 관계가 모호해지면 화살표(`->`)나 최소한의 연결어를 유지합니다.
- **정보는 전부 보존**하고 표현만 정돈합니다. (원 가이드의 "압축하되"는 이 앱에서는 "표현만 정돈하되"로 읽습니다.) 의심스러우면 원문 문장을 거의 그대로 쓰세요.
- **약어는 항상 병기**: 자극추구(Novelty Seeking).
- **암기 단서·니모닉·두문자어는 그대로** 살립니다.
- **부호 표기는 한 맵 안에서 통일**합니다. 화살표는 `->`, 강조는 `**굵게**` 로 통일하세요. 원자료에서 굵게·밑줄·색으로 강조한 부분은 `**굵게**` 로 보존합니다.
- **따옴표는 실제 문자**로: 작은따옴표 ‘ ’, 큰따옴표 “ ” 를 그대로 입력하세요. `&#x2019;` 같은 HTML 엔티티 문자열을 넣지 않습니다.

## 5. 문법 레퍼런스

### 5.1 파일 구조
````md
---
title: "맵 이름"
layout: logic-right
---

# 중심 주제

- 1단계 가지
  - 2단계 가지
    - 3단계 가지
- 또 다른 1단계 가지
````
- `layout`: `mindmap`(중심에서 좌우로 퍼짐, 기본) 또는 `logic-right`(오른쪽으로 펼침, 순서·절차·깊은 계층에 적합)
- frontmatter의 `id:` 는 쓰지 마세요(가져올 때 앱이 정합니다). `title:` 에 `:` 가 있으면 큰따옴표로 감쌉니다.

### 5.2 노드와 속성
```
- 노드 글 {color=red tags=시험,중요 collapsed}
```
- 속성은 줄 끝의 `{ }` 안에 공백으로 구분: `color=` (red, orange, yellow, green, blue, purple, gray 또는 `#e03131` 같은 hex), `tags=` (쉼표로 구분, 공백 없이), `collapsed`(처음부터 접어 둠)
- 값에 공백이 있으면 `key="두 단어"`
- 속성은 줄의 **맨 끝**에만 둡니다. 노드 글 중간에 `{` `}` 를 쓰지 마세요. (글 끝이 `}` 로 끝나는 내용이면 뒤에 한 글자라도 더 붙이세요.)
- 6단계 정리에서는 속성을 **꼭 쓸 필요가 없습니다.** 사용자가 요청할 때만 쓰세요.

### 5.3 메모(포스트잇)
노드 **바로 아래**에 한 단계 더 들여쓴 `> ` 줄들. **첫 줄은 `> 📌 `** 로 시작합니다.
````md
- 프로세스 vs 스레드
  > 📌 스레드는 코드·데이터·힙을 **공유**하고 스택만 따로 가진다.
  >
  > - 장점: 문맥 교환이 빠름
  > - 단점: 한 스레드의 오류가 전체에 영향
````
- 메모 안에서는 마크다운이 전부 됩니다: **굵게**, 목록, 표, 수식, 코드블록(`> ` 를 줄마다 붙여서)
- 빈 줄도 `>` 만 적어 이어 주세요 (메모가 끊기지 않게)
- 메모는 **노드로 풀기 어려운 긴 인용, 코드, 수식 블록, `[AI 보충]`** 에 쓰세요. 원자료의 일반 내용은 메모가 아니라 노드(§4)로 풉니다.

### 5.4 여러 줄 노드
노드 아래에 한 단계 더 들여쓴 **일반 텍스트 줄**은 그 노드 본문의 다음 줄입니다. (부연 설명을 같은 노드 안에 두는 방법)
```
- 교착상태 4조건
  상호배제, 점유와 대기,
  비선점, 환형 대기
```
줄이 `- `, `> `, `1. ` 로 시작해야 한다면 앞에 `\` 를 붙여 이스케이프하세요.

### 5.5 인라인 서식 (노드 글과 메모 모두)
| 쓰는 법 | 결과 |
|---|---|
| `**굵게**`, `*기울임*`, `` `코드` `` | 서식 |
| `$E = mc^2$` | 수식(LaTeX, KaTeX). 메모에서는 `$$ … $$` 블록 수식도 가능 |
| `==빈칸==` | **암기 모드에서 가려지는 부분** (§6) |
| `질문 :: 답` | **플래시카드** 한 장 (§6) |

### 5.6 다른 맵·페이지로 링크
`[[폴더/맵이름.mm]]`, `[[폴더/맵이름.mm#^노드ID|표시할 글]]`. 대상이 **이미 앱에 있을 때만** 쓰세요. 없는 대상은 취소선으로 보입니다. 확실하지 않으면 링크를 쓰지 말고 글로만 적으세요.

### 5.7 같은 맵 안의 연결 (ID를 직접 정하는 유일한 경우)
연결 대상 노드에 **영문 소문자·숫자 4~10자**의 ID를 직접 붙이고, 다른 노드에서 `[[#^그ID|표시글]]` 로 가리킵니다. ID는 맵 안에서 중복되면 안 됩니다. 이 경우가 아니면 ID는 만들지 마세요.

## 6. 암기용으로 쓰는 법 (선택)

**전체 보존 정리가 기본이고, 카드는 사용자가 원할 때 덧입히는 기능**입니다. 카드 문법을 쓰더라도 **정보를 줄이면 안 됩니다.** (`용어 :: 설명` 은 같은 내용을 다르게 표기할 뿐입니다.)

| 쓰는 법 | 만들어지는 것 |
|---|---|
| `정의할 용어 :: 설명` | 질문/답 카드 1장. `::` 양쪽 모두 내용이 있어야 하고, 앞뒤에 **공백 한 칸**씩 |
| `선점형: ==RR==, SRTF` | 빈칸 카드. 빈칸 하나당 1장(한 노드에 빈칸이 둘이면 2장) |
| 메모 안의 `==빈칸==` | 같은 방식으로 카드 |
| `{tags=시험}` | 복습할 때 태그로 범위를 고를 수 있음. 부모의 태그는 하위가 물려받음 |

- 사용자가 "카드로도 쓰고 싶다"고 하면, 정의형 항목은 `용어 :: 설명`, 외워야 할 수치·용어는 `==빈칸==` 으로 표기하세요. 빈칸은 **짧은 핵심어**(1~4단어)만 가립니다.
- 카드 문법이 없는 노드도 앱의 **가리기 모드**(노드를 가렸다 열었다 하며 떠올리기)에서 그대로 쓸 수 있습니다. 그래서 **6단계로 전체를 담아 두기만 해도** 복습이 됩니다.

## 7. 완성 예시 (이 예시들은 앱에서 오류 없이 읽히는지 자동 검증됩니다)

### 7.1 문법 총정리 예시

````markdown
---
title: 운영체제 핵심
layout: mindmap
---

# 운영체제

- 프로세스 관리 {color=blue}
  - 프로세스 vs 스레드 {tags=시험,중요}
    > 📌 스레드는 코드·데이터·힙을 **공유**하고 스택만 따로 가진다.
    >
    > | 구분 | 프로세스 | 스레드 |
    > |---|---|---|
    > | 메모리 | 독립 | 공유 |
    > | 문맥 교환 | 느림 | 빠름 |
    - 프로세스 :: 실행 중인 프로그램, 독립된 메모리 공간
    - 스레드 :: 프로세스 안의 실행 흐름
  - CPU 스케줄링 ^cpu
    - 선점형: ==RR==, SRTF
    - 비선점형: ==FCFS==, SJF
    - 평균 대기시간 $W = \frac{\sum w_i}{n}$
- 교착상태 {color=red tags=시험}
  - 4가지 조건
    상호배제, 점유와 대기,
    비선점, 환형 대기
  - 데드락 :: 서로 상대의 자원을 기다리며 영원히 멈춘 상태
  - 예방 방법 {collapsed}
    - 점유와 대기 방지: 자원을 ==한꺼번에== 요청
    - 환형 대기 방지: 자원에 ==번호==를 매겨 순서대로 요청
- 메모리 관리 {color=green}
  > 📌 주소 변환 예시
  >
  > ```python
  > def translate(page, offset, table):
  >     return table[page] * PAGE_SIZE + offset
  > ```
  - 페이징
    - 내부 단편화가 생긴다
  - 세그멘테이션
    - 외부 단편화가 생긴다
  - 스케줄링과의 연결 [[#^cpu|CPU 스케줄링]]
````

이 예시에서 쓰인 것: frontmatter, 색(`color`), 태그, 접힘(`collapsed`), 표·코드블록이 든 메모, 수식, 여러 줄 노드, `::` 카드, `==빈칸==`, 같은 맵 내 링크(`^cpu` ↔ `[[#^cpu|…]]`).

### 7.2 6단계 전체 보존 정리 예시

레벨 0(제목)부터 레벨 5까지, 나열 분리·표 풀이·절차·예시·부연 줄바꿈·약어 병기가 모두 들어 있습니다. (내용은 구조를 보이기 위한 예시입니다.)

````markdown
---
title: "10주차: 객관적 성격검사"
layout: logic-right
---

# 10주차: 객관적 성격검사

- 성격의 측정
  - 정의적 특성을 측정하는 방법
    - 투사적 방법
      - 모호한 자극 제시
        - 무의식적 느낌·정서·태도를 이끌어냄
      - 장점·단점
        - 반응의 자유도가 높음
        - 해석에 검사자의 주관이 개입될 수 있음
    - 객관적 방법
      - 구조화된 문항에 응답
        - 채점·해석 기준이 정해져 있음
        - 규준과 비교해 점수를 해석
- 객관적 검사의 해석
  - 점수 해석 기준
    - T점수
      - 평균 50, 표준편차 10
    - 65T 이상 -> 임상적으로 의미있는 상승
      (T점수 65는 평균보다 1.5 표준편차 높은 점수)
  - 해석 절차
    - 1) 타당도 확인
    - 2) 척도별 T점수 확인
    - 3) 상승 척도의 종합 해석
      - 예: 상승 척도가 여러 개이면 척도 간 관계까지 함께 해석
- 기질 및 성격검사(TCI)
  - 기질 척도
    - 4개 기질 척도로 구성
      - 자극추구(Novelty Seeking)
        - 새로운 자극에 끌리고 충동적인 경향
      - 위험회피(Harm Avoidance)
        - 불안하고 조심스러운 경향
      - 사회적 민감성(Reward Dependence)
        - 타인의 인정과 보상에 민감한 경향
      - 인내력(Persistence)
        - 보상이 없어도 지속하려는 경향
  - 청소년용
    - 청소년에 적합한 내용·어휘로 문항 수정
````

이 예시에서 보이는 처리:
- **나열 분리**: "4개 기질 척도로 구성"은 레벨 3, 그 아래 4개를 각각 레벨 4 노드로
- **절차**: 단계 묶음은 레벨 3, 각 단계는 `1) 2) 3)` 을 적은 레벨 4
- **예시**: 관련 항목 아래에 `예: …`
- **부연**: 같은 노드 안에서 줄바꿈 (`65T 이상 …` 노드의 둘째 줄)
- **약어 병기**: `자극추구(Novelty Seeking)`

## 8. 출력 전 점검표

**형식**
- [ ] 코드블록 안에 **파일 내용만** 있고, 첫 줄이 `---` 인가 (보고는 코드블록 밖)
- [ ] `title:` 에 콜론이 있으면 큰따옴표로 감쌌는가
- [ ] 중심 주제(`# …`)가 **정확히 하나**인가
- [ ] 들여쓰기가 **공백 2칸 단위**이고 탭이 없으며, 자식이 부모보다 정확히 한 단계만 깊은가
- [ ] 메모의 첫 줄이 `> 📌 ` 로 시작하고, 모든 메모 줄에 `> ` 가 붙어 있는가
- [ ] `{ }` 속성이 줄 맨 끝에 있고 `tags=` 쉼표 뒤에 공백이 없는가
- [ ] 노드 ID(`^abcd`)를 **새로 만들어 넣지 않았는가** (예외 §5.7)
- [ ] 존재하지 않을 수 있는 `[[링크]]` 를 쓰지 않았는가
- [ ] 목록 밖에 설명 문단을 쓰지 않았는가 (맵에 안 보임)
- [ ] 이미지(`![](…)`)를 쓰지 않았는가

**6단계 구조**
- [ ] 제목성(레벨 0~1)과 항목성(레벨 3~5)이 구분되어 있는가
- [ ] 레벨을 건너뛴 곳이 없는가 (필요한 곳에 중간 헤더 추가)
- [ ] 형제 항목이 같은 레벨로 통일되어 있는가
- [ ] 나열형 항목이 한 노드에 뭉치지 않고 분리되어 있는가
- [ ] 표·그림이 텍스트 계층으로 풀려 있고 **모든 셀·수치**가 들어 있는가
- [ ] 약어 병기, 암기 단서·니모닉이 보존되어 있는가
- [ ] 문체가 개조식으로 일관적인가, 따옴표가 엔티티 텍스트로 깨지지 않았는가

**전체 보존**
- [ ] 원자료의 **모든 슬라이드·페이지·절**을 하나씩 대조했는가
- [ ] 수치·단위·정의·분류·예시·예외·조건("단", "다만")이 하나도 빠지지 않았는가
- [ ] 중요도를 스스로 판단해 뺀 것이 없는가
- [ ] 원자료에 없는 내용을 덧붙이지 않았는가 (보충은 메모의 `[AI 보충]`)
- [ ] 제외한 것과 `[판독불가]` 항목을 보고에 적었는가
- [ ] 분량이 많아 나눴다면 레벨 1 경계에서 끊고 `(n/N)` 을 붙였는가

## 9. 고급: PC에서 Vault 폴더를 직접 쓰는 경우

PC에서 앱을 실행하면 모든 데이터는 Vault 폴더의 평문 파일입니다. Claude Code 같은 도구가 폴더를 직접 편집할 수 있고, 앱이 켜져 있으면 바로 화면에 반영됩니다. 자세한 규칙은 Vault 안의 `AGENTS.md` (원본: `docs/FORMAT.md`).

```
Vault/
  과목/운영체제.mm.md          ← 맵
  과목/운영체제/pages/스케줄링.md   ← 팝업 페이지 (긴 설명, 표, 코드, 수식)
  과목/운영체제/assets/a.png      ← 이미지 (메모·페이지에서만 사용)
```
- 노드에서 페이지로 연결: `- CPU 스케줄링 [[과목/운영체제/pages/스케줄링]]`
- 편집 후 검사: `npm run lint:map -- "Vault/과목/운영체제.mm.md"`

## 10. 복사해서 쓰는 요청 예시

**강의자료 → 6단계 전체 보존 맵 (기본)**
> 위 가이드를 따라 아래(첨부) 강의자료를 `.mm.md` 하나로 만들어 줘. **6단계 논리구조**로 정리하고, **요약하지 말고 내용을 누락 없이 전부** 담아 줘 (§3). 수치·정의·예시·예외·표의 모든 셀 포함. `layout: logic-right`. 분량이 많으면 대주제 단위로 나눠서 출력하고, 끝나면 누락 점검 보고를 써 줘. 자료: …

**긴 자료를 나눠서**
> 이 자료는 길어서 한 번에 안 될 거야. 가이드의 §3-8대로 대주제 경계에서 나눠 출력해 줘. 한 파트를 낼 때마다 "계속"을 기다려 줘. 절대 줄여서 한 번에 맞추지 마.

**누락 점검 (두 번째 패스)**
> 위에서 만든 맵을 원자료와 처음부터 대조해서 빠진 내용만 찾아 줘. "어느 노드 아래에 무엇을 추가할지"로 먼저 나열하고, 내가 확인하면 반영한 전체 파일을 다시 출력해 줘.

**카드까지 덧입히기**
> 방금 맵의 내용은 그대로 두고(줄이지 말고), 정의형 항목은 `용어 :: 설명`, 외워야 할 수치·용어는 `==빈칸==` 으로 바꿔서 전체 파일을 다시 출력해 줘. 시험 중요 항목에는 `{tags=시험}`.

**기존 맵 고치기**
> 아래는 내가 쓰는 맵 파일이야. 노드 ID(`^…`)와 `{속성}` 은 절대 바꾸지 말고, "○○ 챕터에 빠진 내용을 추가하고 틀린 내용을 고쳐 줘". 내용을 줄이지 말고 파일 전체를 다시 출력해 줘. 파일: …

**구조만 먼저 검토**
> 먼저 레벨 0~2(강의 제목, 대주제, 세부주제)만 목록으로 보여 줘. 내가 확인하면 그다음에 레벨 3~5까지 **전체 내용**을 채운 `.mm.md` 를 만들어 줘.
