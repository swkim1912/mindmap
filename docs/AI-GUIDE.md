# 마인드맵 앱 — AI 작성 가이드

> **이 문서를 통째로 Claude 채팅이나 다른 AI에게 붙여넣고 요청하세요.**
> AI가 `.mm.md` 형식의 마크다운을 만들어 주면, 사이트의 **⇅ → 가져오기**(파일) 또는 **텍스트 붙여넣기**로 새 맵을 만들 수 있습니다.

---

## 1. 사람을 위한 사용법 (1분)

### 새 맵을 AI에게 만들게 하기
1. 이 문서 전체를 AI 채팅에 붙여넣습니다. (사이트의 ⇅ 대화상자 → **AI 가이드 복사** 버튼으로 복사할 수 있습니다.)
2. 자료와 함께 요청합니다. 예:
   - "아래 강의 노트를 운영체제 맵으로 만들어 줘. 시험에 나올 정의는 `질문 :: 답` 카드로, 외울 용어는 ==빈칸== 으로."
   - "정보처리기사 데이터베이스 과목을 챕터별 가지로 정리하고, 챕터마다 핵심 개념 5개씩 카드로 만들어 줘."
3. AI가 **코드블록 하나**로 준 마크다운을 복사합니다.
4. 사이트에서 가져옵니다.
   - **붙여넣기:** ⇅ → "텍스트 붙여넣어 가져오기"에 붙여넣고 **가져오기** (폰에서 가장 편함)
   - **파일:** `이름.mm.md` 로 저장해서 ⇅ → "파일로 가져오기"
5. 가져온 뒤 맵 위쪽에 **⚠ 해석 경고**가 있으면 마우스를 올려 어느 줄이 문제인지 확인하고, 그 내용을 AI에게 알려 고쳐 달라고 하세요.

### 이미 있는 맵을 AI에게 고치게 하기
1. 사이트에서 맵을 열고 **⇅ → Markdown(.mm.md)** 으로 내보냅니다. (또는 Vault 폴더의 `.mm.md` 파일)
2. 파일 내용을 AI에게 주고 "노드 ID(`^abcd`)는 바꾸지 말고 이렇게 고쳐 줘: …" 라고 요청합니다.
3. AI가 준 **전체 파일**을 가져옵니다. 같은 이름이 있으면 `이름 (2)` 로 새로 만들어지므로 비교한 뒤 옛 맵을 삭제하세요.
   - PC에서 Vault 폴더를 직접 쓰고 있다면 그 파일에 덮어쓰면 열린 화면에 바로 반영됩니다.

### 가져올 수 있는 것
| 형식 | 결과 |
|---|---|
| **이 문서의 형식 (`.mm.md`, `.md`)** | 태그·색·메모·카드 문법까지 그대로. 확장자가 `.md` 여도 내용을 보고 자동 판별 |
| 일반 마크다운 (제목 `#` + 목록 `-`) | 제목과 목록 구조만 가지로 (속성·메모 문법 없음) |
| OPML, XMind(.xmind) | 구조와 메모 |

> **페이지(긴 설명 문서)는 가져오기로 만들 수 없습니다.** 긴 설명·표·코드·수식은 노드의 **메모(포스트잇, `> 📌`)** 안에 쓰세요. 메모는 마크다운을 전부 지원합니다. (PC에서 Vault 폴더에 직접 파일을 둘 수 있다면 §7 참고)

## 2. AI에게: 출력 규칙 (반드시 지킬 것)

당신은 **마인드맵 앱용 파일**을 만드는 도우미입니다. 사용자가 자료를 주면 아래 규칙으로 `.mm.md` 하나를 출력하세요.

1. **파일 전체를 코드블록 하나**에 담아 출력합니다. 코드블록은 ` ````markdown ` (백틱 4개)로 열고 ` ```` ` 로 닫으세요. 메모 안에 백틱 3개짜리 코드블록이 들어갈 수 있기 때문입니다. (3장의 `md` 블록은 문법 조각을 보여 주는 설명용이고, 출력할 파일은 §5 처럼 완성된 `markdown` 블록 하나입니다.)
2. 설명, 인사, 요약은 **코드블록 밖**에 짧게 쓰세요. 코드블록 안에는 파일 내용만 둡니다.
3. 맨 위에 frontmatter(`---` 블록)를 두고, 그다음 `# 중심 주제` 한 줄, 그 아래에 들여쓰기 목록(`- `)으로 가지를 씁니다.
4. **들여쓰기는 공백 2칸**입니다. 탭을 쓰지 마세요.
5. **노드 ID(`^abcd`)를 새로 만들지 마세요.** 새 노드는 ID 없이 쓰면 앱이 붙입니다. (예외: 같은 맵 안에서 다른 노드로 연결하는 링크가 필요하면 §3.7 참고)
6. 가지(노드) 글은 **짧게**: 한 줄 30자 안팎의 키워드·구. 긴 설명은 노드가 아니라 **메모**에 씁니다.
7. 맵 구조: 1단계 가지 5~9개, 깊이 3~4단계. 한 노드 아래 자식은 7개 이하가 보기 좋습니다.
8. **이미지는 쓰지 마세요.** (노드에는 이미지를 넣을 수 없고, 가져오기로 이미지 파일을 만들 수도 없습니다.)
9. 목록(`- `) 밖의 일반 문단은 맵에 표시되지 않습니다. 설명은 메모로 옮기세요.
10. 수정 요청이면: **기존 노드의 ID와 `{속성}` 은 그대로 유지**하고, 파일 전체를 다시 출력하세요.

## 3. 문법 레퍼런스

### 3.1 파일 구조
````md
---
title: 맵 이름
layout: mindmap
---

# 중심 주제

- 1단계 가지
  - 2단계 가지
    - 3단계 가지
- 또 다른 1단계 가지
````
- `layout`: `mindmap`(중심에서 좌우로 퍼짐, 기본) 또는 `logic-right`(오른쪽으로 펼침, 순서·절차에 적합)
- frontmatter의 `id:` 는 쓰지 마세요(가져올 때 앱이 정합니다).

### 3.2 노드와 속성
```
- 노드 글 {color=red tags=시험,중요 collapsed}
```
- 속성은 줄 끝의 `{ }` 안에 공백으로 구분: `color=` (red, orange, yellow, green, blue, purple, gray 또는 `#e03131` 같은 hex), `tags=` (쉼표로 구분, 공백 없이), `collapsed`(처음부터 접어 둠)
- 값에 공백이 있으면 `key="두 단어"`
- 속성은 줄의 **맨 끝**에만 둡니다. 노드 글 중간에 `{` `}` 를 쓰지 마세요.

### 3.3 메모(포스트잇)
노드 **바로 아래**에 한 단계 더 들여쓴 `> ` 줄들. **첫 줄은 `> 📌 `** 로 시작합니다.
````md
- 프로세스 vs 스레드
  > 📌 스레드는 코드·데이터·힙을 **공유**하고 스택만 따로 가진다.
  >
  > - 장점: 문맥 교환이 빠름
  > - 단점: 한 스레드의 오류가 전체에 영향
````
- 메모 안에서는 마크다운이 전부 됩니다: **굵게**, 목록, 표, 수식, 코드블록(`> ` 를 줄마다 붙여서)
- 빈 줄도 `>` 만 적어 이어 주세요 (메모가 끊기지 않게)

### 3.4 여러 줄 노드
노드 아래에 한 단계 더 들여쓴 **일반 텍스트 줄**은 그 노드 본문의 다음 줄입니다.
```
- 교착상태 4조건
  상호배제, 점유와 대기,
  비선점, 환형 대기
```
줄이 `- `, `> `, `1. ` 로 시작해야 한다면 앞에 `\` 를 붙여 이스케이프하세요.

### 3.5 인라인 서식 (노드 글과 메모 모두)
| 쓰는 법 | 결과 |
|---|---|
| `**굵게**`, `*기울임*`, `` `코드` `` | 서식 |
| `$E = mc^2$` | 수식(LaTeX, KaTeX). 메모에서는 `$$ … $$` 블록 수식도 가능 |
| `==빈칸==` | **암기 모드에서 가려지는 부분** (§4) |
| `질문 :: 답` | **플래시카드** 한 장 (§4) |

### 3.6 다른 맵·페이지로 링크
`[[폴더/맵이름.mm]]`, `[[폴더/맵이름.mm#^노드ID|표시할 글]]`. 대상이 **이미 앱에 있을 때만** 쓰세요. 없는 대상은 취소선으로 보입니다. 확실하지 않으면 링크를 쓰지 말고 글로만 적으세요.

### 3.7 같은 맵 안의 연결 (ID를 직접 정하는 유일한 경우)
연결 대상 노드에 **영문 소문자·숫자 4~10자**의 ID를 직접 붙이고, 다른 노드에서 `[[#^그ID|표시글]]` 로 가리킵니다. ID는 맵 안에서 중복되면 안 됩니다. 이 경우가 아니면 ID는 만들지 마세요.

## 4. 암기용으로 쓰는 법 (이 앱의 핵심)

별도 설정 없이 **본문에 쓴 문법이 곧 카드**가 됩니다.

| 쓰는 법 | 만들어지는 것 |
|---|---|
| `정의할 용어 :: 설명` | 질문/답 카드 1장. `::` 양쪽 모두 내용이 있어야 하고, 앞뒤에 **공백 한 칸**씩 |
| `선점형: ==RR==, SRTF` | 빈칸 카드. 빈칸 하나당 1장(한 노드에 빈칸이 둘이면 2장) |
| 메모 안의 `==빈칸==` | 같은 방식으로 카드 |
| `{tags=시험}` | 복습할 때 태그로 범위를 고를 수 있음. 부모의 태그는 하위가 물려받음 |

좋은 카드 만들기:
- **한 카드에는 한 가지만** 묻습니다. 정의 → `::`, 나열형(조건 4가지 등) → 노드 하나에 빈칸 여러 개.
- 빈칸은 **짧은 핵심어**(1~4단어)만 가립니다. 문장 전체를 가리지 마세요.
- 질문 쪽에 단서를 충분히 넣으세요: `TCP 3-way handshake 순서 :: SYN → SYN+ACK → ACK`
- 시험에 중요한 것엔 `{tags=시험}`, 헷갈리는 것엔 `{tags=혼동}` 처럼 **태그 이름을 일관되게** 쓰세요.
- 카드 문법이 없는 노드도 앱의 **가리기 모드**(노드를 가렸다 열었다 하며 떠올리기)에서 그대로 쓸 수 있습니다.

## 5. 완성 예시 (이 예시는 앱에서 오류 없이 읽히는지 검증되어 있습니다)

````markdown
---
title: 운영체제 핵심
layout: mindmap
---

# 운영체제

- 프로세스 관리 {color=blue}
  - 프로세스 vs 스레드 {tags=시험,중요}
    > 📌 스레드는 코드·데이터·힙을 **공유**하고 스택만 따로 가진다.
    >
    > | 구분 | 프로세스 | 스레드 |
    > |---|---|---|
    > | 메모리 | 독립 | 공유 |
    > | 문맥 교환 | 느림 | 빠름 |
    - 프로세스 :: 실행 중인 프로그램, 독립된 메모리 공간
    - 스레드 :: 프로세스 안의 실행 흐름
  - CPU 스케줄링 ^cpu
    - 선점형: ==RR==, SRTF
    - 비선점형: ==FCFS==, SJF
    - 평균 대기시간 $W = \frac{\sum w_i}{n}$
- 교착상태 {color=red tags=시험}
  - 4가지 조건
    상호배제, 점유와 대기,
    비선점, 환형 대기
  - 데드락 :: 서로 상대의 자원을 기다리며 영원히 멈춘 상태
  - 예방 방법 {collapsed}
    - 점유와 대기 방지: 자원을 ==한꺼번에== 요청
    - 환형 대기 방지: 자원에 ==번호==를 매겨 순서대로 요청
- 메모리 관리 {color=green}
  > 📌 주소 변환 예시
  >
  > ```python
  > def translate(page, offset, table):
  >     return table[page] * PAGE_SIZE + offset
  > ```
  - 페이징
    - 내부 단편화가 생긴다
  - 세그멘테이션
    - 외부 단편화가 생긴다
  - 스케줄링과의 연결 [[#^cpu|CPU 스케줄링]]
````

이 예시에서 쓰인 것: frontmatter, 색(`color`), 태그, 접힘(`collapsed`), 표·코드블록이 든 메모, 수식, 여러 줄 노드, `::` 카드, `==빈칸==`, 같은 맵 내 링크(`^cpu` ↔ `[[#^cpu|…]]`).

## 6. 자주 하는 실수 (출력 전에 점검하세요)

- [ ] 코드블록 안에 **파일 내용만** 있고, 첫 줄이 `---` 인가
- [ ] 중심 주제(`# …`)가 **정확히 하나**인가
- [ ] 들여쓰기가 **공백 2칸 단위**이고 탭이 없는가 (자식은 부모보다 정확히 한 단계만 깊게)
- [ ] 메모의 첫 줄이 `> 📌 ` 로 시작하고, 모든 메모 줄에 `> ` 가 붙어 있는가
- [ ] `{ }` 속성이 줄 맨 끝에 있고 `tags=` 쉼표 뒤에 공백이 없는가
- [ ] 노드 ID(`^abcd`)를 **새로 만들어 넣지 않았는가** (예외 §3.7)
- [ ] 노드 글이 너무 길지 않은가 (긴 내용은 메모로)
- [ ] `::` 양옆에 공백이 있고 양쪽 모두 내용이 있는가
- [ ] 빈칸 `==…==` 안에 `=` 가 없고, 한 줄에서 닫혔는가
- [ ] 존재하지 않을 수 있는 `[[링크]]` 를 쓰지 않았는가
- [ ] 목록 밖에 설명 문단을 쓰지 않았는가 (맵에 안 보임)
- [ ] 이미지(`![](…)`)를 쓰지 않았는가

## 7. 고급: PC에서 Vault 폴더를 직접 쓰는 경우

PC에서 앱을 실행하면 모든 데이터는 Vault 폴더의 평문 파일입니다. Claude Code 같은 도구가 폴더를 직접 편집할 수 있고, 앱이 켜져 있으면 바로 화면에 반영됩니다. 자세한 규칙은 Vault 안의 `AGENTS.md` (원본: `docs/FORMAT.md`).

```
Vault/
  과목/운영체제.mm.md          ← 맵
  과목/운영체제/pages/스케줄링.md   ← 팝업 페이지 (긴 설명, 표, 코드, 수식)
  과목/운영체제/assets/a.png      ← 이미지 (메모·페이지에서만 사용)
```
- 노드에서 페이지로 연결: `- CPU 스케줄링 [[과목/운영체제/pages/스케줄링]]`
- 편집 후 검사: `npm run lint:map -- "Vault/과목/운영체제.mm.md"`
- 맵 파일을 옮기면 같은 이름의 폴더(`운영체제/`)도 함께 옮겨야 합니다.

## 8. 복사해서 쓰는 요청 예시

**교재·강의 노트 → 맵**
> 위 가이드대로 아래 자료를 `.mm.md` 하나로 만들어 줘. 1단계 가지는 챕터, 깊이는 3~4단계. 정의는 `::` 카드로, 외울 용어는 `==빈칸==`으로. 시험에 중요한 항목에는 `{tags=시험}`. 긴 설명은 메모(`> 📌`)에 넣고 노드는 짧게. 자료: …

**암기 카드 중심**
> 아래 내용으로 암기 맵을 만들어 줘. 모든 말단 노드가 `질문 :: 답` 또는 `==빈칸==` 카드가 되게. 한 카드는 한 가지만 묻고, 질문에 단서를 충분히 넣어 줘. 내용: …

**기존 맵 고치기**
