# 마인드맵 Vault 파일 포맷 (AI 편집 가이드)
<!-- format-version: 2 -->

이 폴더는 마인드맵 앱의 데이터 폴더(Vault)입니다. 모든 데이터는 평문 Markdown이므로 직접 읽고 편집해도 됩니다.
앱이 실행 중이면 파일 변경이 즉시 화면에 반영됩니다.

## 폴더 구조

```
Vault/
  AGENTS.md                      ← 이 문서 (앱이 관리)
  정보처리기사/                   ← 폴더 = 과목/분류. 자유롭게 만들고 옮겨도 됩니다
    운영체제.mm.md                ← 맵 파일 하나
    운영체제/                     ← 맵 이름과 같은 폴더 = 그 맵에 딸린 파일
      pages/스케줄링.md           ← 팝업 페이지 (긴 설명, 표, 코드, 이미지)
      assets/20261013-1.png       ← 첨부 이미지
  .mindmap/                      ← 앱 내부 데이터(히스토리, 휴지통). 편집하지 마세요
```

맵 파일을 옮기거나 이름을 바꿀 때는 같은 이름의 딸린 폴더도 함께 옮기세요(앱에서 하면 자동으로 함께 옮겨지고, 다른 파일의 `[[링크]]`도 갱신됩니다).

## 맵 파일 (`*.mm.md`)

```markdown
---
id: map_k2x9          # 맵 고유 ID (바꾸지 마세요)
title: 운영체제
layout: mindmap        # mindmap(좌우 방사형) | logic-right(오른쪽으로 펼침)
---

# 운영체제 ^root

- 프로세스 관리 ^a1b2
  - 프로세스 vs 스레드 {color=red tags=시험,중요} ^c3d4
    > 📌 포스트잇 메모. 여러 줄은
    > 이렇게 이어서 씁니다. **Markdown**, $수식$, 이미지도 됩니다.
    - 프로세스 :: 실행 중인 프로그램 ^e5f6
  - CPU 스케줄링 [[정보처리기사/운영체제/pages/스케줄링]] {collapsed} ^i9j0
    - 선점형: ==RR==, SRTF ^k1l2
- 해시 테이블 연결 [[정보처리기사/자료구조.mm#^h1|해시 테이블]] ^q7r8
```

### 규칙

1. **구조**: `# 제목` 한 줄이 중심 주제, 그 아래 들여쓰기 목록(`- `)이 가지입니다. 들여쓰기는 **공백 2칸**이 표준입니다(4칸, 탭도 읽힘).
2. **노드 ID**: 줄 끝의 `^영숫자`가 노드 ID입니다.
   - 기존 노드의 ID는 **절대 바꾸거나 지우지 마세요.** 다른 맵의 링크와 동기화가 ID에 의존합니다.
   - **새 노드는 ID 없이 써도 됩니다.** 앱이 자동으로 부여합니다.
   - 노드를 옮길 때는 ID를 그대로 둔 채 줄(과 하위 줄)을 옮기세요.
   - 같은 ID를 두 번 쓰지 마세요(복사 시 주의).
3. **속성**: ID 바로 앞의 `{...}` 블록. `key=value` 또는 플래그.
   - `color=red` (red, orange, yellow, green, blue, purple, gray 또는 #hex)
   - `tags=시험,중요` (쉼표 구분)
   - `collapsed` (접힌 상태)
   - 값에 공백이 있으면 `key="두 단어"`.
4. **포스트잇(메모)**: 노드 바로 아래, 한 단계 더 들여쓴 `> ` 줄. 첫 줄은 `> 📌 `로 시작합니다. 내용은 Markdown(굵게, 목록, 수식 `$..$`, 코드, 이미지 `![](...)`)입니다.
5. **여러 줄 노드**: 노드 아래 한 단계 들여쓴 일반 텍스트 줄은 노드 본문의 다음 줄입니다. `- `, `> `, `1. `로 시작하는 줄은 앞에 `\`를 붙여 이스케이프합니다.
6. **노드 본문 인라인 문법**:
   - `**굵게**`, `*기울임*`, `` `코드` ``, `$수식$` (KaTeX)
   - `==빈칸==` : 암기 모드에서 가려지는 부분
   - `질문 :: 답` : 플래시카드 (앞면 :: 뒷면)
   - `[[링크]]` : 아래 "링크" 참고
7. 맵 구조로 해석되지 않는 줄(목록 밖 일반 문단 등)은 보존되지만 맵에 표시되지 않습니다.

## 링크 `[[...]]`

노드 본문, 포스트잇, 페이지 어디에든 쓸 수 있습니다. 대상은 **확장자 없는 파일 경로**입니다.

| 쓰는 법 | 의미 |
|---|---|
| `[[폴더/맵이름.mm]]` | 다른 맵 (파일 `폴더/맵이름.mm.md`) |
| `[[폴더/맵이름.mm#^노드ID]]` | 다른 맵의 특정 노드. 이동하면 그 노드가 선택됨 |
| `[[폴더/맵이름/pages/페이지]]` | 팝업 페이지 (파일 `…/페이지.md`) |
| `[[…\|표시명]]` | 화면에 보일 이름 지정. 예: `[[폴더/자료구조.mm#^h1\|해시 테이블]]` |
| `[[#^노드ID]]` | 같은 맵 안의 노드 |

- 경로는 Vault 기준 전체 경로를 권장합니다. 끝부분만 써도(`[[스케줄링]]`, `[[자료구조.mm]]`) 같은 이름의 파일을 찾으며, 여러 개면 현재 파일과 가까운 것을 고릅니다.
- 대상이 없으면 화면에 취소선으로 표시됩니다. `^노드ID`는 노드 줄 끝의 ID와 같아야 합니다.
- 앱에서 파일을 옮기거나 이름을 바꾸면 링크가 자동으로 갱신됩니다. 직접 옮겼다면 링크도 직접 고쳐 주세요.
- 한 노드에 링크가 있으면 화면의 ↗ 로 이동합니다. 맵의 노드를 가리키는 링크가 있으면 대상 노드에 `↩ N`(역링크) 표시가 생깁니다.

## 팝업 페이지 (`pages/*.md`)

일반 Markdown 파일입니다. 맵 노드에 `[[…/pages/이름]]` 링크를 걸면 그 노드에서 열립니다.

```markdown
---
title: "CPU 스케줄링"
---

# CPU 스케줄링

본문. **굵게**, 표, 코드 블록(```python), 수식 $x^2$ / $$\sum_i x_i$$, 빈칸 ==호위 효과==,
이미지 ![설명](../assets/20261013-1.png), 링크 [[폴더/자료구조.mm#^h1|해시 테이블]]
```

- 맨 위 `---` 블록(frontmatter)의 `title` 은 창 제목으로 쓰입니다. 없어도 됩니다.
- 여러 노드가 같은 페이지를 가리켜도 됩니다.

## 이미지

- 이미지는 **맵 노드 본문에는 넣을 수 없고**, 포스트잇과 팝업 페이지에만 넣습니다.
- 맵에 딸린 폴더의 `assets/` 에 두고 **그 파일 기준 상대 경로**로 씁니다.
  - 맵 파일의 포스트잇: `![](운영체제/assets/a.png)`
  - `운영체제/pages/` 안의 페이지: `![](../assets/a.png)`
- 경로의 공백은 `%20` 으로 씁니다. 지원 형식: png, jpg, gif, webp, svg, avif.

## 편집 후 검사

```bash
npm run lint:map -- "Vault/경로/파일.mm.md"
```

경고(중복 ID, 해석 안 되는 줄 등)가 출력되면 수정하세요.
