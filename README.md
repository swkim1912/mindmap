# 마인드맵 (학습·암기용)

로컬 Markdown 파일 기반 마인드맵. 기획은 [SPEC.md](SPEC.md), 파일 포맷은 [docs/FORMAT.md](docs/FORMAT.md) 참고.

## 실행

```bash
npm install
npm start          # 빌드 후 http://localhost:4321
```

개발 모드 (코드 수정 시 자동 반영): `npm run dev` → http://localhost:5173

### Vault(데이터 폴더) 위치

기본값은 이 저장소의 `vault/` 폴더입니다. 다른 곳(예: OneDrive)을 쓰려면:

```powershell
$env:MINDMAP_VAULT = "D:\공부\Vault"; npm start
```

처음 실행하면 예시(`예시/` 폴더의 맵 2개와 페이지 1개)와 AI용 설명서(`AGENTS.md`)가 만들어집니다.
서버 포트는 `MINDMAP_PORT` 로 바꿀 수 있습니다 (기본 4321).

## 폴더 관리 · 휴지통

PC와 모바일 모두 같은 방식입니다.

| 하고 싶은 일 | 방법 |
|---|---|
| 새 맵·새 폴더 | 사이드바 위의 ＋ 맵 / ＋ 폴더 (선택한 폴더 안에 생성). 빈 폴더도 PC↔모바일에 동기화됨 |
| 이름 바꾸기·이동·삭제 | 행 오른쪽 **⋯** 버튼, PC는 오른쪽 클릭, 모바일은 **길게 누르기** → 메뉴(모바일은 아래에서 올라오는 시트) |
| 이름 바꾸기 | 그 자리에서 입력, Enter 적용 / Esc 취소. 맵의 딸린 파일, 다른 파일의 `[[링크]]`, 복습 기록이 함께 따라감 |
| 이동 | 메뉴의 "이동…"에서 폴더 선택. PC는 끌어다 놓기도 가능 |
| 삭제 | 먼저 "맵 1 · 페이지 3 · 이미지 2를 옮깁니다 / 끊어질 링크 N개"를 보여 줌 → 휴지통으로. 하단에 **되돌리기** 가 10초간 표시됨 |
| 휴지통 | 사이드바 아래 🗑 휴지통. 복원 / 영구 삭제 / 비우기. **30일** 보관 후 자동 영구 삭제 |

- 휴지통은 기기 간에 공유됩니다. 어느 기기에서 지웠든 다른 기기 휴지통에서 복원할 수 있고, 복원하면 모든 기기에 돌아옵니다. (클라우드에도 삭제된 내용이 30일간 남으므로 Supabase 저장 용량을 조금 씁니다)
- 복원할 자리에 같은 이름이 이미 있으면 `이름 (복원)` 으로 복원합니다.
- 이름 변경·이동은 휴지통 목록에 나타나지 않습니다. 이동하는 동안 다른 기기에서 옛 이름의 파일을 고치면 옛 이름이 다시 생길 수 있습니다(고친 쪽을 살리는 규칙).
- 삭제한 파일은 PC의 `.mindmap/trash/<삭제 시각>/` 폴더에 그대로 들어가므로 탐색기에서도 꺼낼 수 있습니다.

## 내보내기 · 가져오기 · 백업

툴바의 **⇅** 버튼에서 합니다.

| 기능 | 내용 |
|---|---|
| 내보내기 | Markdown(원본), OPML, XMind(.xmind), FreeMind(.mm), Anki 카드(.txt), SVG, PNG, PDF(인쇄 창에서 저장) |
| 가져오기 | XMind(.xmind, 최신 형식), OPML, Markdown 제목·목록(.md/.txt), 이 앱의 맵(.mm.md) → 현재 폴더에 새 맵으로 만듦 |
| 이전 버전 | PC 전용. 저장할 때 5분에 한 번 기록(최근 50개)된 버전을 보고 되돌림. 되돌리기 직전 내용도 기록에 남음 |
| 전체 백업 | PC 전용. 맵·페이지·이미지·복습 기록을 zip 하나로. 복원은 zip 을 Vault 폴더에 풀어 넣기 |

- 이미지·PDF 에는 메모(포스트잇)가 포함되지 않고, 원본·OPML·XMind 에는 포함됩니다. FreeMind 는 내보내기만 됩니다.
- 삭제한 파일은 `.mindmap/trash/` 에 그대로 남아 있으니 탐색기에서 꺼내 쓰면 됩니다.

## 클라우드 동기화 (선택, 모바일용)

PC의 Vault를 Supabase에 미러링합니다. 원본은 항상 PC 폴더이고, 설정하지 않으면 동기화는 꺼져 있습니다.

1. Supabase 대시보드 → Authentication → Add user 로 본인 계정(이메일+비밀번호)을 만들고, Sign In / Providers 에서 **Allow new users to sign up 을 끕니다**.
2. 저장소 루트에 `.env.sync` 파일을 만듭니다 (git에 올라가지 않음).

```
MINDMAP_SUPABASE_URL=https://<프로젝트>.supabase.co
MINDMAP_SUPABASE_KEY=<publishable 키 (sb_publishable_...)>
MINDMAP_SYNC_EMAIL=<위에서 만든 이메일>
MINDMAP_SYNC_PASSWORD=<비밀번호>
```

3. `npm start` 를 다시 실행하면 "클라우드 동기화: 켜짐"이 표시됩니다. 파일이 바뀔 때, 모바일에서 바뀔 때, 30초마다 동기화합니다. 상태는 `GET /api/sync`.

- 맵(`.mm.md`)은 노드 단위로 3-way 병합합니다. 같은 노드를 양쪽에서 고쳤거나 페이지가 충돌하면 PC 내용을 남기고 클라우드 내용을 `이름 (충돌 사본).md` 로 보존합니다.
- 한쪽에서 지우고 다른 쪽에서 고쳤으면 고친 쪽을 살립니다. 지워진 파일은 `.mindmap/trash/` 로 갑니다.
- 이미지는 10MB 이하만 올라갑니다. 빈 폴더 목록도 함께 동기화됩니다.

## 모바일 앱 (PWA)

같은 웹 UI를 휴대폰에서 쓰는 방식입니다. 로그인하면 Supabase와 동기화하고, 맵·페이지·이미지·복습 기록을 기기에 저장해 **오프라인에서도 열람·편집**합니다. 인터넷이 다시 연결되면 PC와 같은 규칙으로 합쳐집니다.

- **배포**: 저장소를 Vercel에 연결하면 됩니다 (`vercel.json` 설정 포함, 환경 변수 불필요). Supabase 주소와 publishable 키는 `apps/web/.env` 에 들어 있으며, 공개되어도 안전한 값입니다. 데이터는 로그인(RLS)으로 보호됩니다.
- **설치**: 배포된 주소를 휴대폰 브라우저로 열어 로그인한 뒤, 브라우저 메뉴의 "홈 화면에 추가"를 누르세요.
- **조작**: 맵을 한 손가락으로 끌어 이동, 두 손가락으로 확대/축소. 노드를 탭해 선택하고 하단 줄의 버튼(편집·하위·동급·삭제·메모·페이지·접기·취소)을 씁니다. ☰ 로 맵 목록을 엽니다.
- **모바일에서 못 하는 것**: 이전 버전 복원과 전체 백업(PC 전용), 노드 끌어서 옮기기(마우스 전용)
- PC에서 개발 중에 모바일 모드를 보려면 `http://localhost:5173/?cloud` 를 여세요.

## AI로 맵 만들기 (Claude 채팅 등 어떤 AI든)

[docs/AI-GUIDE.md](docs/AI-GUIDE.md) 가 AI용 사용설명서입니다. 강의자료를 **6단계 논리구조(강의 제목 → 대주제 → 세부주제 → 내용 → 보조 내용 → 세부 내용)** 로 정리하고, 요약하지 않고 **내용을 누락 없이 전부** 담도록 지시합니다 (긴 자료는 대주제 단위로 나눠 출력, 끝에 누락 점검 보고). 그 밖에 파일 형식, 카드 문법, 출력 규칙, 완성 예시, 점검표, 요청 예시가 들어 있습니다. 앱 안에서는 사이드바의 **⇅ → AI로 맵 만들기 → AI 가이드 복사**로 받을 수 있습니다.

1. AI 채팅에 가이드를 붙여넣고 자료와 함께 요청합니다.
2. AI가 준 마크다운을 복사해서 **⇅ → 붙여넣은 내용으로 새 맵 만들기** (코드블록 표시가 같이 복사돼도 됩니다). 파일로 받았다면 "파일로 가져오기".
3. `.md` 파일이어도 내용에 태그·메모·`^id` 같은 이 앱 문법이 있으면 자동으로 맵 형식으로 읽습니다. 일반 제목·목록 마크다운은 구조만 가져옵니다.
4. 기존 맵 수정: ⇅ → Markdown(.mm.md) 으로 내보내 AI에게 주고, 돌려받은 전체 파일을 가져오면 "이름 (2)" 로 만들어집니다 (노드 ID는 유지되므로 비교 후 옛 맵 삭제).

가이드의 완성 예시는 자동 테스트(`packages/core/test/import.test.ts`)가 실제로 읽히는지 검사하므로, 문법을 바꾸면 가이드도 함께 고쳐야 테스트가 통과합니다.

## AI로 편집하기 (Claude Code 등, PC)

Vault 폴더의 `.mm.md` / `.md` 파일을 Claude Code 등으로 직접 편집하면 열린 화면에 즉시 반영됩니다.
앱에 저장 안 된 편집이 있으면 맵은 노드 ID 기준으로 자동 병합하고, 페이지는 충돌 시 어느 쪽을 쓸지 묻습니다.
편집 후 검사:

```bash
npm run lint:map -- vault/예시/운영체제.mm.md
```

## 데이터 안전장치

- 저장은 임시 파일에 쓴 뒤 교체(원자적 쓰기)
- 덮어쓰기 전 내용을 `.mindmap/history/`에 보관 (파일당 5분 간격, 최근 50개)
- 삭제는 `.mindmap/trash/`로 이동
- 해석할 수 없는 줄은 버리지 않고 보존
- 폴더 이동 중 일부만 실패하면 원래대로 되돌림 (맵 파일과 딸린 폴더가 어긋나지 않게)
- 페이지/메모의 Markdown은 화면에 그리기 전에 정화(DOMPurify)해서 파일 내용으로 스크립트가 실행되지 않음
